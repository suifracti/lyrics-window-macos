## 0. 收口总结：方向 D (Final Direction D)

在完成 A / B / C 三套方案的公平探索后，我们收口形成了 Lyric Island 统一的产品方向 **方案 D**：

1. **安静默认播放体验（源自方案 A）**：
   * 工作台关闭时极度安静，当前行是唯一视觉主角；
   * 正常连接、Provider、模型名称、排轴算法与工程数据完全隐藏；
   * 歌词默认**只展示原文 + (翻译 OR Ruby 二选一)**，彻底解决多层堆叠失控问题。

2. **歌曲工作台架构（源自方案 B）**：
   * 包含明确但克制的 `[ 􀍵 歌曲工作台 ]` 入口；
   * Wide 使用右侧 380px 原生 Inspector，Small 使用 Bottom Sheet；
   * 全面洗牌为用户任务语言（歌词、翻译、读音、时间同步、历史版本、导入导出），隐藏工程术语。

3. **轻量行级快捷语境（源自方案 C）**：
   * Hover 歌词行时显示极轻微触发点，点击唤出行级微控（`[ 译文 | 读音 | 时间 ]`）；
   * 行级微控补充但**不替代**完整歌曲工作台。

4. **19 个真实渲染画面**：
   * 原型文件 `docs/phase-3/phase-3-1-mockups/index.html` 中的 19 个 Final Direction 按钮均包含完全独立的 DOM 结构渲染。

## 2. 唯一产品原则与 Phase 3.0 审计收敛

三套方案均严格遵循 Lyric Island 的最高事实来源：

* **产品定位**：原生 macOS 歌词伴侣。平时安静跟随 Spotify 展示歌词，需要时展开为能翻译、标注、编辑、排轴和保存个人版本的歌词工作台。
* **最高信息原则**：默认界面**只显示用户完成当前任务真正需要的内容**。隐藏 Provider 名、Hash、SQLite、Migration、DP、Whisper、S3A/S3B、confidence 置信度数字。
* **双层结构**：
  1. *零操作歌词伴侣*：播放即看，全自动补全、翻译与排轴；
  2. *完整 DIY 歌词工作台*：来源、候选、翻译、Prompt、读音、排轴、版本与导入导出均可接管。
* **独立多表面**：顶部胶囊（紧凑状态+控制+最多一行歌词）与桌面歌词（自由位置+多行+锁定+穿透）是两个独立 WindowController，绝对不合并。

## 3. 三套高保真视觉方案深度剖析

### 方案 A：安静优先 (Quiet-First)

#### 3.1.1 命题与重点探索
将默认歌词伴侣做到**最大程度克制**，接近“打开后无需理解或操作”的极致体验。
* **默认主窗口**：绝不保留任何常驻状态图标、Provider 标签或工程圆点。
* **高级功能发现**：当鼠标移动到窗口顶部 30px 区域时，极简工具栏淡入显示；在歌词行右键或点击标题时唤出 Level 2 快捷 Popover。

#### 3.1.2 主要矛盾
* **极度克制 vs 功能发现性**。

#### 3.1.3 信息层级 L1–L4 映射
* **Level 1 (默认)**：仅显示封面 + 歌名/艺人 + 播放进度 + 歌词原文 + 最多 1 层辅助文字。
* **Level 2 (语境)**：顶部悬停淡出工具栏、右键歌词快捷菜单、极简空态与重试按钮。
* **Level 3 (工作台)**：通过点击歌曲标题弹出的轻量 Popover，提供显示层 toggle 和 [展开高级工作台] 入口。
* **Level 4 (全局)**：双 Tab 极简设置，默认仅显示外观与字号，高级工程控制隐入底部置灰入口。

---

### 方案 B：伴侣 + 工作台双层 (Companion + Workbench)

#### 3.2.1 命题与重点探索
默认歌词伴侣与完整歌曲工作台形成**明确但连贯的双层结构**。
* **默认伴侣**：干净美观的 45/55 分栏歌词伴侣，右上角拥有一个极其清晰的 `[ 􀍵 歌曲工作台 ]` 按钮。
* **歌曲工作台形态**：点击按钮后，从主窗口右侧平滑滑出 **380px 的侧边 Inspector 面板**（或在小窗模式下弹为 Sheet），收纳 4 大核心区块：
  1. *歌词来源与候选*（LRCLIB / 本地 / 切换候选）；
  2. *翻译与读音*（AI Prompt 预设 / MeCab 校准）；
  3. *排轴与时间轴*（Whisper+DP 状态 / 手动打轴接管）；
  4. *版本历史与导入导出*（3 个历史版本时间轴 / LRC 导出）。

#### 3.2.2 主要矛盾
* **明确模式结构 vs 视觉和操作连续性**。

#### 3.2.3 信息层级 L1–L4 映射
* **Level 1 (默认)**：45/55 分栏歌词画布，顶部带清晰的工作台展开 Pill 按钮。
* **Level 2 (语境)**：工作台按钮 hover 高亮，提供当前歌曲品质与已排轴角标。
* **Level 3 (工作台)**：380px 侧栏 Inspector，一次性完整收纳所有深度 DIY 操作，关闭后恢复安静。
* **Level 4 (全局)**：侧边栏独立分类，包含“常规设置”与“高级工程仪表盘”。

---

### 方案 C：语境融合 (Contextual Fusion)

#### 3.3.1 命题与重点探索
**不设置明显的“进入工作台”模式**，而是让操作随当前歌词、当前状态和用户动作逐层出现。
* **语境展开**：点击当前歌词行，原地弹出行级微型工具条（`[ 修正译文 | 调整读音 | 校准时间 ]`）；点击歌曲标题弹出曲目元数据 Popover；点击连接状态点弹出网络与 Provider 诊断。
* **无模式切换**：不需要“打开/关闭工作台”，所有操作在看歌词的过程中随手完成。

#### 3.3.2 主要矛盾
* **自然语境展开 vs 发现性和高级操作效率**。

#### 3.3.3 信息层级 L1–L4 映射
* **Level 1 (默认)**：歌词画布，当前行右侧带有极隐微的 `...` 语境触发点。
* **Level 2 (语境)**：hover 或点击任意歌词行，整行高亮并展开行级内联工具。
* **Level 3 (工作台)**：由多个特定元素的语境 Popover 组合承载，不设单一集中面板。
* **Level 4 (全局)**：Search-First 搜索优先设置，支持关键词直接定位高级工程选项。
