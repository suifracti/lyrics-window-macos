# 方案 A：安静优先 (Quiet-First) 详细设计规范与状态映射

## 1. 命题与核心哲学
将默认歌词伴侣做到最大程度克制，接近“打开后无需理解或操作”的体验。默认主窗口绝不显示任何常驻状态图标、Provider 名称、数据库或者排轴工程细节。所有的控制能力在悬停、右键或需要时隐柔淡入。

## 2. 状态映射表 (1-30)

| # | 状态名称 | 方案 A 视觉与交互表现 |
|---|---------|----------------------|
| 1 | Wide 播放中 | 45/55 分栏，只有歌词 + 封面 + 极简播放控制。工具栏完全隐藏（opacity 0）。无连接圆点 |
| 2 | Wide Hover / 语境 | 鼠标移入顶部 30px 时，极简工具栏淡入 (3 个图标：窗口模式、搜索、设置)。右键歌词弹出 Level 2 快捷菜单 |
| 3 | Small 播放中 | 520px 宽度自适应，封面与元数据收起为 180px 顶部卡片，歌词居中。不留任何无用空白 |
| 4 | Lyrics Focus | 680px 宽纯歌词阅读，去除非必要控制，当前行字号提升至 32pt |

## 3. 优势与风险评估
- **优势**：极度干净，将 macOS 原生歌词伴侣的“安静”做到了极致。
- **风险**：高级能力隐藏极深，新用户可能不知道如何开启翻译、读音或手动搜索。
